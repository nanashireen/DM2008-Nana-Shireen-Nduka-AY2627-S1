For my DM2008 Mini Project, I decided to create Flappy Bird: Underwater, an ocean-themed version of the classic Flappy Bird game. I chose an underwater setting because I liked the way it looked and felt that it offered something different from the original game's sky setting. Instead of controlling a bird flying between pipes, players guide a submarine through underwater obstacles, using upward taps to move and avoiding tall seaweed along the way.

To turn the starter code into a fully playable game, I created three game states: start, playing and game over. I used basic vector physics to control the submarine's movement, with gravity set to 0.45 and an upward thrust of -8.0 when the player presses a key. I also wanted the game to become more challenging as the player progressed, so I added a difficulty system that gradually reduces the time between obstacles from 90 frames to a minimum of 50 frames as the score increases.

I implemented a scoring system that checks the submarine's position against each obstacle. Whenever the submarine successfully passes an obstacle without colliding with it, the obstacle is marked as passed and the player's score increases by one. The updated score is then displayed on the screen, allowing players to keep track of their progress.

Visually, I wanted the game to have a retro arcade feel, so I replaced the original circular player and rectangular obstacles with custom pixel-art sprites. I used a pixelated submarine, seaweed and an underwater background. I also loaded Google's Tiny5 font to make the text match the overall aesthetic. To make the game feel more alive, I added a gentle bobbing animation to the submarine on the start screen and created a bubble particle system that follows the submarine's propeller as it moves.

One of the main challenges I faced was getting the images to load correctly. Initially, I tried using an asynchronous `setup()` function to load the sprites. However, this caused the images to load repeatedly while the game was running, resulting in duplicated submarines and seaweed appearing in overlapping layers across the canvas.

After looking into p5.js tutorials on asset loading, I realised that the problem came from how the images were being loaded. I fixed this by moving the image-loading code into the `preload()` function, which ensures that the assets are loaded before the rest of the game begins. This resolved the duplication issue and allowed the sprites to appear correctly. Through this process, I gained a better understanding of how p5.js handles asset loading and how important it is to manage the game's setup correctly.
